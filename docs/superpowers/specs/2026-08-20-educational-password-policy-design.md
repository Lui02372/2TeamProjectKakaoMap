# 교육용 비밀번호 정책 변경 설계

## 목적

교육용 부산여행 가이드에서 `id01 / pw01`, `id02 / pw02`처럼 기억하기 쉬운 예시 계정을 사용할 수 있게 한다. 현재 회원가입 요청은 비밀번호 최소 8자 제한 때문에 `pw01`을 422 요청 검증 오류로 거부한다.

## 변경 범위

- 회원가입 요청의 비밀번호 최소 길이를 8자에서 4자로 낮춘다.
- 로그인 요청과 Argon2 비밀번호 검증 방식은 변경하지 않는다.
- 데이터베이스에는 평문 비밀번호를 저장하지 않는다.
- Supabase SQL Editor에서 반복 실행할 수 있는 예시 계정 등록 SQL을 추가한다.
- 예시 계정은 `id01 / pw01`, `id02 / pw02`이며 표시 이름은 각각 `부산 여행자 1`, `부산 여행자 2`로 한다.

## 데이터 흐름

일반 회원가입은 프론트엔드가 사용자명과 비밀번호를 백엔드에 전송하고, 백엔드는 4자 이상인지 검증한 뒤 Argon2id로 해시하여 Supabase의 `app_users`에 저장한다. 예시 SQL은 미리 생성된 Argon2id 해시만 저장하며 `user_profiles`를 같은 사용자 ID에 연결한다.

## 중복 실행 처리

예시 SQL은 `normalized_username` 충돌 시 해당 예시 계정의 사용자명, 비밀번호 해시, 활성 상태를 갱신한다. 프로필은 `user_id` 충돌 시 표시 이름을 갱신한다. 따라서 SQL Editor에서 다시 실행해도 예시 계정이 중복 생성되지 않는다.

## 오류 처리

- 4자 미만 비밀번호는 기존과 동일하게 422로 거부한다.
- `id01`, `id02`는 사용자명 최소 4자 및 허용 문자 규칙을 만족한다.
- 예시 SQL은 마이그레이션 `0002_busan_guide.sql`이 먼저 적용되어 있어야 한다.

## 테스트

- `SignupRequest`가 `pw01`을 허용하는 테스트를 먼저 추가하고 기존 코드에서 실패하는지 확인한다.
- 3자 비밀번호가 계속 거부되는지 검증한다.
- 전체 백엔드 및 프론트엔드 테스트를 실행한다.
- 로컬 API에서 `pw01` 형식의 회원가입 요청이 422 요청 본문 오류를 내지 않는지 확인한다.

## 제외 범위

운영 서비스 수준의 비밀번호 강도 정책, 이메일 인증, 비밀번호 재설정, 계정 잠금 기능은 이번 교육용 변경에 포함하지 않는다.
